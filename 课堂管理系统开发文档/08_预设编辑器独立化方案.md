# 预设编辑器独立化 · 方案调整设计

> 状态：待确认 · 2026-09-02
> 对应系统：初二信息技术硬件实践课课堂管理系统（v1 单应用 → v2 三应用 → v3 五模块闭环）
> 本方案只调整**预设的生产与流转**，不动 v3 已定稿的课堂状态流转（上课/活动/计时/策略）。

---

## 1. 调整动因

v2/v3 交付中，预设编辑能力以两种形态存在：

| 形态 | 位置 | 问题 |
|------|------|------|
| Web 编辑器 | `teacher/public/editor/`，寄居在教师端 HTTP 服务里 | 编辑器与服务强耦合——办公电脑想编辑预设，得先起整套教师端服务（依赖 Node + broker 环境），且编辑发生在"教室那台机器" |
| 预设管理面板 | 大屏 `manage.js`（CRUD） | 把"编辑"塞进了教室大屏，大屏职责过重，且与独立编辑器功能重复 |

**业务现实**：教师编辑预设发生在**办公电脑**（办公室网段），教室大屏运行在**教室教师机**（教室网段）——两端通常**不在同一局域网**，不能假设 LAN 直连。预设必须能跨网络流转。

**本次调整目标**：预设编辑器重新定位为**安装在办公电脑的独立应用**（功能完整、内容详尽、可独立打包分发），教室大屏退化为**预设的接收与使用端**，两端通过**预设包文件**交换数据。

---

## 2. 新架构总览（分离式）

```
┌─────────────────────────────────┐        ┌──────────────────────────────────┐
│  办公电脑 · Preset Studio        │        │  教室教师机 · 大屏系统             │
│  （独立桌面应用，完全离线可用）    │        │  （teacher server + 大屏 Web）    │
├─────────────────────────────────┤        ├──────────────────────────────────┤
│  · 班级预设 完整 CRUD             │        │  · 预设导入（选文件→校验→预演→入库）│
│  · 活动预设 完整 CRUD             │        │  · 预设列表（只读摘要 + 删除卫生）  │
│    （器材/任务模板/计时默认）       │        │  · 上课：下拉选班级预设            │
│  · 器材库维护（eqId/名称/分类）     │        │  · 发布活动：下拉选活动预设/模板    │
│  · 预设包 导出 / 导入              │        │  · 实时课堂控制（计时/锁定/SSE）    │
│  · 本地库 preset.db（独立于教室）   │        │  · 教室库 classroom.db            │
└───────────────┬─────────────────┘        └──────────────▲───────────────────┘
                │  预设包文件 *.kctpreset                    │
                │  （U盘 / 网盘 / 微信文件，离线主路径）       │
                └────────────────────────────────────────────┘
                    可选增强：两端同一网段时，支持一键"发送到教室"
                    （studio 推送 → server 接收端，后续迭代）
```

**职责边界总原则：预设的生产在办公端，消费在教室端。** 编辑（创建/修改/删除）只在 Preset Studio 发生；大屏端只负责接收、查看、选用。数据单向主路径为 办公→教室；保留 教室→办公 导出（备份/迁移回编辑）。

## 3. 预设数据流转协议（核心）

### 3.1 预设包文件格式 `.kctpreset`（JSON，UTF-8）

```json
{
  "pkg": "kct-preset-package",
  "schemaVersion": 1,
  "exportedAt": 1788362000000,
  "source": "preset-studio/1.0.0",
  "classes": [
    {
      "presetId": "CP-1A2B3C4D",
      "name": "初二(1)班",
      "totalSeats": 48,
      "groupSize": 6,
      "note": "东机房",
      "updatedAt": 1788300000000
    }
  ],
  "activities": [
    {
      "presetId": "AP-9F8E7D6C",
      "name": "焊接入门",
      "category": "焊接",
      "timed": true,
      "durationSec": 480,
      "equipment": [
        { "eqId": "DEV-BOARD", "eqName": "开发板", "category": "主控", "preset": 1 }
      ],
      "taskTemplates": [ { "title": "点亮 LED", "desc": "第一关" } ],
      "note": "",
      "updatedAt": 1788300000000
    }
  ]
}
```

- `presetId` 由 Studio 生成（`CP-/AP-` + 8 位），**跨机器保持稳定**（合并依据）。
- 所有时间字段用毫秒时间戳，格式统一。

### 3.2 导入合并策略（大屏端接收）

按 `presetId` 逐条比对库中现有数据，导入前先出**预演清单**，教师确认后才落库：

| 情形 | 判定 | 动作 |
|------|------|------|
| 新增 | 库中无此 presetId | 直接入库 |
| 覆盖 | 库中存在且包内 `updatedAt` ≥ 库中 `updatedAt` | 覆盖 |
| 跳过 | 库中存在且包内 `updatedAt` < 库中 `updatedAt` | 跳过并提示（本地较新） |

预演结果：`{ added: N, updated: M, skipped: K }`，逐项列出，确认后批量 upsert（单事务）。

### 3.3 校验规则（导入与导出双端执行）

- `pkg` 标记必须为 `kct-preset-package`，否则拒绝。
- 活动预设：名称非空；`equipment[]` 每项含 eqId/eqName；`durationSec` ∈ [5, 3600]（timed 时必填）；taskTemplates 标题非空。
- 班级预设：名称非空；totalSeats ∈ [1, 99]；groupSize ∈ [1, 20]。
- 未知字段忽略，坏包返回 `E-PKG-01` 并指出具体项。

### 3.4 双向流转

- **办公 → 教室（主路径）**：Studio 全量/勾选导出 → 文件传递 → 大屏"导入预设包" → 预演确认 → 落教室库 → 上课/发布活动即用。
- **教室 → 办公（备份/迁移）**：大屏"导出预设包" → Studio 导入 → 继续编辑（同一合并策略）。
- 两端导入均不改 presetId，保证同一班级/活动在多台机器间引用一致。

## 4. 办公端独立应用：Preset Studio

### 4.1 形态与运行约束

| 项 | 决策 |
|----|------|
| 形态 | Electron 桌面应用（可 electron-builder 打包 Windows 便携版分发） |
| 安装位置 | 教师办公电脑（可多台并存，数据互不共享，靠预设包同步） |
| 运行依赖 | **零外部依赖**：不连 broker、不起 HTTP 服务、不需要教师端环境 |
| 本地存储 | `preset.db.json`（JSON 文件存储起步，避免原生模块 ABI 问题；如需 SQLite 再 electron-rebuild） |
| 窗口 | 1280×860 桌面窗口（复用现有编辑器的深色视觉，功能比现 Web 版更详尽） |

### 4.2 功能清单（比现 Web 编辑器更完整）

1. **班级预设**：CRUD + 座位数/分组校验 + 备注。
2. **活动预设**：CRUD + 器材清单（eqId/eqName/分类/默认数量）+ 任务模板（标题/说明）+ **计时默认配置**（timed/durationSec，v3 字段）。
3. **器材字典**：维护常用器材（分类分组、eqId 引用提示），编辑活动时从字典选入——现 Web 版没有，独立应用补齐。
4. **预设包导入/导出**：全量或勾选导出；导入时预览合并结果（新增/覆盖/跳过）。
5. **校验与提示**：命名冲突、器材引用、计时范围等即时校验。
6. **数据保险**：每次保存写时间戳；导出带 `exportedAt`，供冲突仲裁。

### 4.3 与现资产的复用关系

| 现资产 | 处置 |
|--------|------|
| `teacher/public/editor/` 的 UI 三件套（index.html/styles.css/presets.js 渲染逻辑） | **迁出复用**：搬入 `preset-studio/renderer/`，渲染与表单逻辑基本照搬，数据层替换 |
| 依赖 teacher server API 的 fetch 调用 | 替换为 preload + IPC → 主进程本地 JSON 存储（`preset-studio/main.js` 持有读写，渲染层不可信） |
| `shared/icons.js` Lucide 图标源 | 继续引用，满足 P0-1 |

## 5. 教室大屏端改造（接收与使用）

### 5.1 服务端新增

| 端点 | 说明 |
|------|------|
| `POST /api/v1/presets/import` | body 为预设包对象 → 预演 `{added, updated, skipped, items[]}`；`?commit=true` 落库（单事务 upsert） |
| `GET /api/v1/presets/export` | 导出当前教室库全量预设包（供备份/回迁编辑） |

### 5.2 服务层

`preset.service.js` 新增：
- `previewImport(pkg)`：schema 校验 + 比对，产出预演清单（不落库）
- `commitImport(pkg)`：按预演结果单事务 upsert
- `exportPackage()`：组包（复用现有 toClassPreset/toActivityPreset DTO）

### 5.3 大屏 UI 收编

| 现功能（manage.js） | 调整 |
|------|------|
| 新建/编辑班级、活动预设（saveClass/saveActivity） | **移除**（编辑职责归 Studio） |
| 删除预设（removeClass/removeActivity） | 保留（数据卫生：清掉误导的预设） |
| 预设列表（renderClassList/renderActivityList） | 保留，改只读摘要 + 显示来源/时间 |
| 管理面板入口（btn-manage → section#manage） | 更名"预设管理"→ 精简为：**导入预设包（文件选择→预演→确认）+ 列表 + 删除 + 导出** |

### 5.4 兼容与测试影响

- 现有 `GET/POST/PUT/DELETE /presets/*` 路由**保留**（大屏删除用 + smoke/routes 测试兼容），仅 UI 不再暴露编辑入口。
- 新增：`preset.service` 导入导出单测、routes.js 计数、大屏 dom 测试（manage 面板改为导入流）、端到端（Studio 导出→大屏导入→上课选用，见第 8 节）。
