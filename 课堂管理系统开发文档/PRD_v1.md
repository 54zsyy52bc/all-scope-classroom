## 0. 三项已锁定决策（硬约束，全文遵循）

> 以下决策由项目总监确认，PRD 所有设计不得与之冲突。

1. **学生端形态**：Electron 桌面应用。必须能真实调用操作系统关机命令（`shutdown`），不能依赖浏览器沙箱（浏览器无关机权限）。
2. **物联网服务**：DFRobot 官方 SIoT2（内置并使用），通信同时支持 MQTT（TCP）与 WebSocket，服务端为内网 SIoT2 实例，不依赖公网。
3. **交付范围**：完整可运行 MVP，覆盖「学生端 + 教师端大屏 + SIoT2 + 数据导出 + 自动关机」全链路，须端到端跑通。

## 1. 产品定义

### 1.1 一句话描述
面向初二信息技术硬件实践课，以 SIoT2 物联网消息服务为底座，让学生机自助完成「课前登记/器材领取 → 课中进度反馈 → 课后归还确认 → 自动关机」全流程，教师在大屏一眼掌握全班到课、器材、进度与求助情况，替代人工点名与器材统计。

### 1.2 目标用户
| 用户 | 角色 | 特征 | 核心诉求 |
| --- | --- | --- | --- |
| 初二学生（12–14 岁） | 终端使用者 | 操作能力有限、注意力易分散 | 界面极简、按钮大、三步内完成，不需要理解后台 |
| 信息技术教师 | 主控者 | 熟悉基础 IT、需管理全班 | 大屏一目了然、一键上课/下课/导出、少配置 |
| 机房管理员（R-ADM，可选） | 部署维护 | 学校机房管理员 | 一次部署、可批量下发、易维护、每学期易更新台账 |

### 1.3 核心问题
传统人工点名、器材借还核对、进度问询占用大量教学时间，且容易出错、无法实时掌握求助小组。机房本身已有 PC 与内网，缺乏一套轻量、隐私安全（无摄像头/麦克风）、贴合「初二硬件实践课」流程的数字化工具。

### 1.4 差异化定位（轻量竞品参照）
本工具为学校内部自用，不做商业平台对标，仅列参照以明确边界：

| 参照工具 / 形态 | 与我们关系 | 我们的差异点（为什么选我们） |
| --- | --- | --- |
| Veyon / Watcher（机房监控类） | 同类但不同路线 | 它们以屏幕抓拍、键鼠锁定、远程控制为核心，偏「监控/管控」，涉及隐私且功能过重；我们只做「流程协同」，不抓屏、不锁键鼠，符合初二课堂的轻量诉求 |
| RFID/刷卡实验室签到系统（高校/实训） | 同类理念不同实现 | 它们依赖读卡器/机位电源硬件；我们复用机房现有 PC + SIoT2，零额外硬件采购，部署成本极低 |
| 商用智慧教室 IoT 平台（Tendzone 等） | 同类上层能力 | 它们是全校级 B/S 采购平台，重运维；我们是单机+内网的小型课堂工具，一学期一配置即可 |
| 通用点名/问卷工具（如在线表单） | 部分重叠 | 它们无法联动器材归还、无法自动关机、无实时大屏聚合，且依赖公网；我们全流程内网闭环 |

**一句话差异**：复用机房现有 PC 与 SIoT2，用 MQTT 把「登记—器材—进度—关机」串成一条课堂流水线，零额外硬件、不触隐私、教师一键掌控。

## 2. 用户角色与权限矩阵

> 复用 01 文档角色定义（R-STU / R-TCH / R-ADM），精简呈现。MVP 不引入教师账户体系（见第 4 节 Out-of-Scope）。

| 功能 | 学生 R-STU | 教师 R-TCH | 管理员 R-ADM |
| --- | --- | --- | --- |
| 填写/确认个人信息登记 | 可执行 | 不可（可代重置） | 不可 |
| 领取/归还器材确认 | 可执行 | 不可（可代确认） | 不可 |
| 任务状态反馈（进行中/完成/求助） | 可执行 | 不可 | 不可 |
| 触发本机自动关机 | 下课指令下可执行 | 可远程触发 | 可 |
| 上课 / 下课控制 | 不可 | 可执行 | 可执行 |
| 发布 / 结束任务 | 不可 | 可执行 | 不可 |
| 查看大屏聚合数据 | 仅本机状态 | 可执行 | 可执行 |
| 导出课堂报表 | 不可 | 可执行 | 可执行 |
| 配置机房座位表 / 器材台账 / SIoT2 主题与凭据 | 不可 | 基础可改 | 全权 |

**权限设计要点**
- 学生机在登记完成后锁定为「已登记」，仅教师可重置（防止误改/作弊）。
- 关机指令仅在下课（return）阶段合法，杜绝误触提前关机（见 04 接口约定）。
- 管理员能力在 MVP 可由教师在教师端兼管（物理隔离的机房教师机），不单独建账号。

## 3. MVP 范围（五个能力域）

> 优先级说明：**P0 = MVP 必须交付（全链路跑通）**；**P1 = 重要增强，时间允许纳入，否则进 Backlog**。
> 验收摘要为「Given/When/Then」式可观测结果，供测试与架构师对齐。

### 3.1 课前登记
| 功能项 | 优先级 | 验收摘要 |
| --- | --- | --- |
| 教师「开始上课」创建会话并广播 start | P0 | Given 系统未上课且已连 SIoT2，When 教师点「开始上课」，Then 全体学生机进入登记界面，大屏到课状态转为「等待登记」 |
| 学生信息登记（姓名/学号/小组） | P0 | Given 学生机在登记界面，When 学生填写并点「确认登记」，Then 上报 checkin，本机锁定为已登记；若座位表已预填则一步核对确认 |
| 器材领取登记（勾选/数量） | P0 | Given 学生机展示器材清单，When 学生核对实物后点确认，Then 上报领取清单，大屏按组/器材聚合「已领/未领」 |
| 实时汇总大屏（到课/未登记/领取率） | P0 | Given 学生陆续登记，When 教师端收到消息，Then 50 台并发下数据 1 秒内反映到大屏，无错漏 |
| 座位表预填（管理员导入后学生仅核对） | P1 | Given 已导入 seats.json，When 学生开机登记，Then 姓名/学号/小组预填，仅需确认一步 |

### 3.2 课中互动
| 功能项 | 优先级 | 验收摘要 |
| --- | --- | --- |
| 教师「发布任务」广播 task | P0 | Given 处于上课态，When 教师点「发布任务」（说明可选），Then 全体学生机高亮当前任务并可反馈状态 |
| 学生任务状态反馈（进行中/完成/求助） | P0 | Given 任务已发布，When 学生点任一状态按钮，Then 单次点击即上报（带时间戳+组号），可随时切换 |
| 小组状态实时矩阵 + 求助高亮 | P0 | Given 某组点「求助」，When 教师端收到，Then 该组色块橙红闪烁并置顶，1 秒内教师可定位 |

### 3.3 课后收尾
| 功能项 | 优先级 | 验收摘要 |
| --- | --- | --- |
| 教师「下课」广播 end，切到归还 | P0 | Given 上课态，When 教师点「下课」，Then 全体学生机切到归还确认界面，大屏进入收尾阶段 |
| 器材归还确认（全部归还勾选） | P0 | Given 归还界面，When 学生清点并点「确认归还」，Then 上报 return(allReturned=true)，大屏显示各组归还完成情况 |
| 全部确认后自动关机 | P0 | Given 所有组均确认归还，When 教师端判定完成，Then 下发 shutdown，学生机弹 10s 提示后调用 OS 关机；若有未确认组，教师可「提醒未确认」或「强制关机」 |

### 3.4 数据导出
| 功能项 | 优先级 | 验收摘要 |
| --- | --- | --- |
| 一键导出四类报表（xlsx/csv） | P0 | Given 课堂结束或进行中，When 教师点「导出」并选范围/格式，Then 生成登记表/任务记录/器材使用/事件日志四类文件，字段完整，且导出不阻塞大屏实时刷新 |
| 导出默认路径与命名规范 | P1 | Given 导出成功，When 文件生成，Then 默认存至教师机「文档/课堂报表/」或 Downloads，文件名含 sessionId 与日期，UTF-8 BOM 防乱码 |

### 3.5 断线重连
| 功能项 | 优先级 | 验收摘要 |
| --- | --- | --- |
| MQTT 断线指数退避重连 | P0 | Given 网络抖动/断网，When 客户端检测断开，Then 按 1s→2s→4s…→30s 封顶重连，重连后自动补发未确认关键状态 |
| 关键状态持久化队列（断网/崩溃不丢） | P0 | Given 断网期间学生点了登记/归还，When 进程崩溃或重启后仍未能发送，Then 本地持久化队列在重连后按序补发，教师端按 msgId 幂等去重 |
| 连接状态常驻指示（已连接/重连中/离线） | P1 | Given 任意时刻，When 连接态变化，Then 学生机与教师端右上角以绿/黄/红三色圆点+文字展示，离线时禁用提交并提示 |

## 4. 明确不做（Out-of-Scope）

| 不做项 | 原因 |
| --- | --- |
| 屏幕抓拍 / 键鼠锁定 / 远程控制学生机 | 偏离「流程协同」定位，涉及隐私，初二课堂不需要监控 |
| 摄像头 / 麦克风采集（人脸考勤等） | NFR-S2 明确不采集与课程无关隐私；且增加硬件与合规成本 |
| 多教师账户体系 / 登录鉴权 | MVP 为单机教师机，靠物理访问控制即可，账户体系留待后续 |
| 多班级同机房并行上课 | MVP 单课堂会话；多班级需不同 SIoT2 项目前缀，非本期目标 |
| 跨公网 / 云同步 / 移动端 App | NFR-S1 仅内网；学校自用无需公网，降低部署与安全风险 |
| 历史统计、排名、成绩分析等增强报表 | 核心闭环优先；导出原始数据已满足，分析留 Backlog |
| 机位电源物理控制（断电继电器） | 超出软件范围，且关机指令已覆盖「关机」诉求 |
| 器材 RFID 实物绑定 / 防丢硬件 | 复用现有 PC+SIoT2，零额外硬件是核心约束之一 |
| 与学校教务/课表系统对接 | MVP 手动建会话即可，对接留后续，避免外部依赖阻塞交付 |

## 5. 非功能需求收敛（沿用 01，MVP 关键项）

| 类别 | 要求 | 优先级 |
| --- | --- | --- |
| 性能 | 50 台并发在线；上报到大屏 ≤ 1s；聚合刷新 ≥ 1Hz 增量渲染；导出（≤50 人×多表）≤ 3s | P0 |
| 可靠性 | 关键消息 QoS=1；断网恢复后关键状态 100% 补传且幂等；学生机异常退出已上报数据不丢（服务端持久化） | P0 |
| 易用性 | 核心操作 ≤ 3 步；主按钮 ≥ 80×80px、文字 ≥ 18pt；状态用颜色+文字双重表达；状态/连接指示常驻 | P0 |
| 兼容性 | 学生机支持 Windows 10/11（64 位），Electron 44.0.0（见 R-1 裁决）；教师端 Chrome/Edge 最新两版 | P0 |
| 安全 | 仅内网；SIoT2 启用账户密码认证、禁用匿名写入；不采集隐私 | P0 |
| 可部署 | 学生机支持批量静默部署（配置文件含 SIoT2 地址/主题前缀/账户）；座位表与器材台账为可编辑配置文件 | P0 |

**图标与视觉约束（团队级）**：状态指示一律用「颜色 + 文字/形状」表达（如绿点=已连接、黄点=重连中、红点=离线；灰块=未开始、蓝块=进行中、绿块=已完成、橙红闪烁块=求助），不使用 emoji 作图标；界面配色禁用紫→粉渐变。

## 6. 风险与缺口（对比 01 文档，需补充决策）

> 以下为现有 01–05 文档未闭合、会阻塞 MVP 落地决策的点。每条给出建议，请项目总监/架构师评审确认。数据库层加固项（t_event_log.msg_id UNIQUE、t_student.machine_id、(session_id,seat) UNIQUE 等 6 条）由架构侧在 ARCH_v1 §9 详细给出，PRD 在此确认其必要性，作为 AC-7 幂等补传与数据正确性的落地支撑。

### R-1 Electron 版本与 Windows 7 兼容性（已裁决）
- **缺口（已闭环）**：01 的 NFR-C1 原要求支持 Windows 7/10/11（32/64 位），但 Electron 自 23 版起已移除 Windows 7 支持，若机房含 Win7 则新版 Electron 无法运行。
- **裁决（总监，已落入 SPEC §4 / ARCH）**：机房全班统一为 **Windows 10/11**，故采用 **Electron 44.0.0**（仅 Win10/11 的较新版本）。NFR-C1 的 Win7 要求随之作废，更新为「学生机支持 Windows 10/11（64 位）」。MVP 构建在 CI 中锁定 Electron 44.0.0 与目标 Windows 运行时。

### R-2 座位表 / 器材台账的初始化配置方式（已裁决）
- **缺口（已闭环）**：01 提到「管理员导入座位表」、03 有 `t_equipment` 表，但种子数据由谁生成、什么格式、如何加载到学生机登记界面未定义。
- **裁决（总监，已落入 SPEC §6 / ARCH）**：采用**配置文件种子**——`seats.json`（座位号→预置小组/可选预填姓名学号）+ `equipment.json`（器材台账 eqId/名称/类别/库存）。教师端首次启动导入，座位表小组字段用于预填登记，器材清单下发至学生机登记与归还界面。本 PRD 原建议与此完全一致；
- **落实建议**：管理员维护这两个 JSON 即可，零数据库操作，符合 NFR-M2「每学期可更新」。

### R-3 学生机离线队列的持久化介质（高优先级，已与架构侧对齐）
- **缺口**：03 写「本地文件/IndexedDB」、04 写「本地队列」，但 Electron 主进程不能用浏览器 IndexedDB；且断线队列量级仅数十条约，过重方案（LevelDB/SQLite）反而增加 50 台分发与编译复杂度。
- **建议**：锁定为 **本地 JSON 文件**（`pending-queue.json`，Node `fs` 写入），遵循架构侧学生端「零原生依赖（仅 `mqtt` 一个纯 JS 包）」硬纪律，保证「绿色包拷入即跑、不触发编译」。未确认消息（checkin/task/return）在主进程落 JSON，进程崩溃/重启后按 `ts` 顺序补发，明确不依赖 IndexedDB。教师端依 `msgId` 幂等去重（04 约定 E-DUP-01）；03 建议 `t_event_log.msg_id UNIQUE` 作为进程重启后的持久化兜底（详见 ARCH_v1 §9）。

### R-4 SIoT2 凭据如何分发到学生机（已裁决）
- **缺口（已闭环）**：04 连接参数要求 `username/password` 必填、NFR-S3 要求启用认证，但账户密码与 broker 地址、端口如何到达 40–50 台学生机未定义。
- **裁决（总监，已落入 SPEC §4 / ARCH §7.3）**：构建期将 `app-config.json` 注入 Electron 打包资源，包含 `brokerIp`、`topicPrefix`（默认 `siot/ict_`，其中 **`siot/` 为 SIoT2 平台固定前缀、不可配置**）、`mqttUsername`、`mqttPassword`、`wsPort`（学生机 WebSocket 端口，默认 1888、路径 `/ws`）、`tcpPort`（教师 Node TCP 端口，默认 1883，见 R-6）；同时提供「网络设置」入口（仅 R-ADM/R-TCH 可见）允许首次启动覆盖。安全方面：凭据以明文存于内网单机配置文件，因 NFR-S1 不触公网可接受，但应在部署文档注明文件权限（仅本机可读）。SIoT2 侧账户需一次性初始化（见 R-5；broker **无「项目名」字段**，主题前缀 `siot/` 平台固定）。凭据泄露的分层缓解（改凭据 + 关 DevTools + shutdown 令牌校验 + OnlyLocalURD=true）已由架构在 ARCH §7.3 给出，待总监定夺是否再加加密。

### R-5 SIoT2 项目/账户/主题权限的一次性初始化（中优先级）
- **缺口**：02/04 假定 SIoT2 已就绪（认证账户 + `siot/ict_*` 主题，`siot/` 为平台固定前缀），但**账户如何创建、匿名写入如何禁用、主题权限如何约束（仅允许该账户发布订阅 `siot/#`）**未定义，NFR-S3「禁用匿名写入」也无落地步骤。（注：SIoT2 无主题级 ACL，且 `siot/` 为平台固定前缀，见 R-10。）
- **建议**：提供 `setup_siot2` 初始化说明/脚本：在 SIoT2 **创建专用账户（用户名/密码，默认 `siot`/`dfrobot`，须改；NFR-S3 禁用匿名写入）**；主题前缀 `siot/` 为 SIoT2 **平台固定、不可配置**，物理主题 `siot/ict_*`（Plan B 两级方案已锁，见 SPEC §5.2），**无需手动建「项目」**。**禁用匿名写入（改 conf 凭据 + `OnlyLocalURD=true`）**、**cleanSession=true（不依赖 broker 持久会话）**。**注意：SIoT V2 无「开启持久化」开关、也无主题级 ACL**——业务消息以 **QoS 1 自动留存于 SIoT 内置库（仅作排障取证，不作业务依据；权威源仍是教师端 SQLite）**；全班共用该账户，订阅隔离限制见 R-10。离线补发不靠 broker 持久会话，而靠**学生端本地 JSON 队列（R-3）+ 应用层 hello→sync 握手（AC-11）**；且 clientId 带机器随机后缀与持久会话所需的稳定 clientId 冲突，故设 cleanSession=true（与 ARCH §5.5 一致，不采用 false）。纳入「一次部署」清单（NFR-M1）。

### R-6 MQTT 与 WebSocket 的传输分工（中优先级）
- **缺口**：决策 2 写「通信走 MQTT + WebSocket」，但 02/04 主要描述 MQTT/TCP(1883)。两者分工未明确，且学生机与教师端的运行时形态不同，传输能力也不同，需按实际形态定死，否则 Phase 3 会建错通道。
- **建议**：明确分工（已与 SPEC_v1 §4/§5、ARCH_v1 §5 对齐，SPEC 为权威契约）：
  - **学生机 Electron（renderer，浏览器环境）走 MQTT over WebSocket —— SIoT2 = 1888，路径 `/ws`**（`ws://<brokerIp>:1888/ws`）。浏览器/renderer **无法打开裸 TCP 套接字**，WebSocket 是唯一可行通道，故学生机只能走 WS，不能走 1883。
  - **教师端 Node 进程走 MQTT over TCP（1883）**（`mqtt://<brokerIp>:1883`）。Node 可直接建 TCP，最稳，且作为**全班唯一聚合点**（订阅 `siot/ict_up|ict_hb|ict_sync`，下发 `siot/ict_cmd`），所有学生报文经此落 SQLite 权威源。
  - **大屏看板浏览器不直连 MQTT**（SPEC §4 纪律 3）。它只通过 HTTP + **SSE**（`/dashboard/stream`）接收 Node 下发的实时数据，不直接订阅 SIoT2。
  - SIoT2 **同时开启 1883（TCP）与 1888（WS）两端口**。注意版本差异：**SIoT2 的 WS 端口是 1888（路径 /ws），不是 SIoT v1 的 8083**——旧文档/旧记忆里的 8083 是 v1 端口，本项目以 v2 的 1888 为准。端口以实际部署核实后写入 `app-config.json` 与教师端配置。

### R-7 自动关机的离线兜底（中优先级）
- **缺口**：04 约定全部确认后广播 `cmd:shutdown`（QoS1）。但 cleanSession=true 下 broker 不重放离线期消息，若某学生机在广播时已离线，它不会收到关机指令；即便之后重连，也需教师端在 sync 握手阶段补发或由教师现场处理。
- **建议**：教师端在「强制关机」前，大屏标注「尚未关机」的离线座位清单；提供「强制关机」兜底按钮（对所有在线机重发）；学生机 reconnect 时经 hello→sync 握手，若本课堂已进入关机阶段则教师端补发 shutdown（与 AC-11 协同）。对始终离线机，由教师现场处理或在下一节课前复位。MVP 不追求 100% 自动覆盖离线机。

### R-8 小组分配方式（低优先级）
- **缺口**：登记界面让学生自选小组，课堂临时争论分组会拖慢登记。
- **建议**：由 `seats.json` 预置小组字段，登记时优先预填、学生可改；既快又减少争议。与 R-2 联动。

### R-9 数据导出默认路径与并发会话（低优先级）
- **缺口**：04 定义了文件名与格式，但默认保存路径、以及是否允许多课堂历史并存未明确。
- **建议**：默认保存到教师机「文档/课堂报表/」，文件名含 `sessionId` 与日期；历史导出按 session 级联查询（03 已设计），MVP 支持「本次/历史」切换（04 已定）。

### R-10 SIoT 无主题级 ACL 的隐私边界（需如实披露，中优先级）
- **缺口**：SIoT V2 不支持主题级 ACL，全班共用一个 SIoT 账户。学生机理论上可订阅 `siot/ict_up`（或 `siot/#` 全量）等上行主题，从而读到其他同学的姓名/学号/器材领取等上行数据。
- **判定**：初二课堂内姓名学号本就班内公开，且全部通信仅限内网（NFR-S1），MVP 可接受。但此限制应在交付前如实披露，避免上线后被质疑。
- **后续**：若日后要求强隔离（如跨班混用机房或涉及敏感数据），必须更换支持主题级 ACL 的 broker（如 EMQX），属于架构级变更，不在 MVP 范围。
- **关联**：与 R-4 凭据分发、R-5 账户初始化一并纳入部署说明。
