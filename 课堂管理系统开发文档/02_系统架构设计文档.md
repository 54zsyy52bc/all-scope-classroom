## 1. 架构概述
系统采用"轻端 + 物联中间件 + 聚合端"三层结构：

- **表现层**：学生机客户端（轻量终端）、教师端大屏看板（Web 聚合）。
- **通信层**：SIoT2 / EasyIoT（MQTT Broker）作为消息总线，负责发布/订阅与可靠传输。
- **数据层**：教师端本地 SQLite（课堂数据落地）；SIoT2 负责消息中转（可开启持久化）；学生机仅保留极小本地缓存（草稿/连接态）。

设计要点：学生机"无状态上报"，所有权威数据集中在教师端；SIoT2 仅做通道，不直接参与业务逻辑，保证可替换为 EasyIoT。

## 3. 通信机制

### 3.1 发布/订阅模型
- 学生机 **订阅** 教师广播主题（接收指令）。
- 学生机 **发布** 本机状态/登记到对应上行主题。
- 教师端 **订阅** 所有学生上行主题 + 广播回执；**发布** 指令到广播主题。
- 采用"主题前缀 + 设备标识"的层次化命名，详见第 4 节。

### 3.2 连接与保活（KeepAlive）
- MQTT `KeepAlive = 30s`；心跳包（PINGREQ/PINGRESP）维持长连接。
- 客户端在 CONNECT 时携带 `cleanSession=false`（会话保留），使离线期间教师端仍可接收重连后的补发。

### 3.3 断线检测与自动重连
```
[连接] → 定时心跳
   │
   ├─ 心跳超时(>1.5×KeepAlive) → 标记"离线"
   │       │
   │       └─ 指数退避重连: 1s → 2s → 4s → ... → 30s(封顶)
   │               │
   │               └─ 重连成功 → 重新订阅 → 补发未确认关键状态(QoS1)
   └─ 正常 → 持续运行
```
- 重连期间本地缓存关键操作（登记/归还/求助），恢复后按序补发。
- 同一消息携带 `msgId` + `ts`，服务端/教师端做幂等去重。

### 3.4 QoS 等级选择
| 消息类别 | QoS | 理由 |
| --- | --- | --- |
| 上课/下课/发布任务/关机 指令 | QoS 1 | 必须送达，可重复 |
| 登记/领取/归还/求助 上报 | QoS 1 | 关键业务，至少一次 |
| 高频心跳/在线心跳 | QoS 0 | 可丢失，开销低 |

### 3.5 阶段消息时序
- **课前**：教师 `上课` → 广播 `cmd/start` → 学生进入登记 → 持续上报 `stu/{id}/checkin`。
- **课中**：教师 `发布任务` → 广播 `cmd/task` → 学生上报 `stu/{id}/task`（status 变化）。
- **课后**：教师 `下课` → 广播 `cmd/end` → 学生上报 `stu/{id}/return` → 全确认后广播 `cmd/shutdown`。

## 4. SIoT2 消息主题规划（Topic Plan）

### 4.1 命名规范
```
<Project>/<Device>/<Sub>
```
- `Project`：课堂项目名，统一为 `ICTClass`（可在配置中修改）。
- `Device`：
  - `TEACHER` —— 教师端
  - `STU_{seat}` —— 学生机，seat 为座位号（01–50）
  - `BROADCAST` —— 教师→全体广播通道
- `Sub`：功能子主题（`cmd` 指令 / `checkin` 登记 / `task` 任务 / `return` 归还 / `status` 在线）。

### 4.2 主题清单
| 主题（Topic） | 方向 | QoS | 说明 |
| --- | --- | --- | --- |
| `ICTClass/BROADCAST/cmd` | 教师→学生 | 1 | 全局指令：start/end/task/shutdown/reset |
| `ICTClass/TEACHER/cmd` | 教师→自身/回执 | 1 | 教师端内部指令与状态 |
| `ICTClass/STU_{seat}/checkin` | 学生→教师 | 1 | 课前登记与器材领取上报 |
| `ICTClass/STU_{seat}/task` | 学生→教师 | 1 | 课中任务状态（进行中/完成/求助） |
| `ICTClass/STU_{seat}/return` | 学生→教师 | 1 | 课后器材归还确认 |
| `ICTClass/STU_{seat}/status` | 学生→教师 | 0 | 在线/心跳（可丢失） |
| `ICTClass/TEACHER/agg` | 学生→教师(聚合回执) | 1 | 学生对广播指令的 ACK（可选） |

> 教师端订阅：`ICTClass/STU_+/#` 与 `ICTClass/BROADCAST/#`（如需）。
> 学生机订阅：`ICTClass/BROADCAST/cmd`、`ICTClass/STU_{own}/#`。

### 4.3 消息体通用结构（JSON）
```json
{
  "msgId": "uuid",
  "ts": 1693400000000,
  "type": "checkin | task | return | cmd | status",
  "seat": "07",
  "group": "G2",
  "payload": { }
}
```

## 5. 模块划分

### 5.1 学生机客户端
| 模块 | 职责 |
| --- | --- |
| 连接管理器 | MQTT 连接、心跳、断线重连、本地缓存补发 |
| 登记模块 | 渲染登记表单、校验、上报 checkin |
| 任务反馈模块 | 渲染任务按钮、上报 task 状态 |
| 归还模块 | 渲染归还确认、上报 return |
| 关机控制器 | 接收 shutdown 指令并调用 OS 关机 |
| 状态指示 | 常驻显示连接态与当前阶段 |

### 5.2 教师端大屏看板
| 模块 | 职责 |
| --- | --- |
| 会话管理器 | 上课/下课/发布任务、阶段状态机 |
| 实时聚合引擎 | 订阅上行主题、解析、更新内存模型 |
| 看板渲染 | 小组矩阵、统计卡、事件流 |
| 指令发布器 | 向 BROADCAST/cmd 下发指令 |
| 数据导出 | 生成 xlsx/csv 报表 |
| 连接管理器 | 同学生机（重连、状态指示） |

### 5.3 服务端（SIoT2）
- 创建 `ICTClass` 项目与账户；开启认证；配置主题权限。
- 可选：开启消息持久化以支持断线补发（依赖 cleanSession=false）。

  |                |                 |
  |--上课(cmd)---->|                 |
  |                |--广播 start---->| 进入登记界面
  |                |<--checkin-------| 填写并提交
  |<--checkin-----|                 |
  | 更新大屏(到课+) |                 |

教师端        SIoT2       学生机
  |--task---->|           |
  |           |--task---->| 高亮任务

```
教师端        SIoT2       学生机
  |--end----->|           |

  | 检查全确认 |           |
  |--shutdown->|           |
  |           |--shutdown->| 执行OS关机
```

## 7. 技术选型建议
| 组件 | 建议 | 说明 |
| --- | --- | --- |
| 学生机客户端 | Web(Chromium封装/Electron) 或 Python+WebView | 简化部署，跨 Win 版本 |
| MQTT 客户端库 | MQTT.js（Web）/ paho-mqtt（Python） | 支持 QoS 与重连 |
| 教师端看板 | Web（Vue/React 或原生）+ WebSocket 本地桥 | 大屏渲染、易投影 |
| 本地数据库 | SQLite | 单文件、零运维 |
| 导出 | SheetJS(xlsx) / PapaParse(csv) | 前端直接生成 |
| 物联服务 | SIoT2（默认）/ EasyIoT（可切换） | 双后端兼容 |

## 8. 扩展性
- 主题前缀与项目名配置化，支持多班级/多机房并行。
- 上行数据含 `group`、`seat`，便于后续按组/座位聚合分析。
- 教师端聚合引擎与渲染解耦，未来可接入历史统计、排名等增强功能。
