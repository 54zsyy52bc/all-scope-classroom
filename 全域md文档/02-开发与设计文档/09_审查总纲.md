# 09 · 审查总纲（较大代码更新后的过审标准）

> 用途：**任何较大代码更新，必须先按本总纲过审全绿，之后才允许 commit + push 仓库。**
> 适用范围：三端源码（teacher / student / preset-studio）、共享契约、配置与文档同步。
> 自动化入口：`classroom-mgmt/check-and-push.sh`（一键跑全量审查 → 全绿才 push）。

---

## 一、自动化审查（必须全绿，14 项）

```bash
cd classroom-mgmt
bash run-tests.sh --full          # 全量：10 项快速 + 真实 broker smoke + net.broker + 门禁
```

| 组 | 项目 | 通过标准 |
|----|------|----------|
| 教师端 | selfcheck / routes / preset-pkg / dashboard.dom | 20 / 46 条 0 重复 / 23 / 34 全过 |
| 办公端 | Preset Studio store / renderer.dom | 36 / 15 全过 |
| 学生端 | protocol / renderer.dom / net.broker | 20 / 29 / 11 全过 |
| 门禁 | 行数（常规 ≤300、db 仓储 ≤320）/ P0 emoji 扫描 | 无超线、UI 代码无 emoji |
| 真机 | 全链路冒烟 smoke（真实 SIoT broker） | 全过（当前基线 77/77） |
| 联调 | 学生端真机联调 net.broker | 全过（11/11） |

任一失败 → **禁止推送**，修到全绿再走下一步。

## 二、一致性审查（人工/脚本核对）

1. **三端共享契约一致**：`topics.js / icons.js / preset-package.js` 双端逐字一致（diff 核验）。
2. **交付副本 = 源码**：`交付包_v4课堂管理系统/{1_PresetStudio,2_教师机,3_学生端}` 与 `classroom-mgmt` 对应文件零差异。
3. **zip 自检**：重打后校验"zip 条目 = 目录文件"、Studio 的 `resources/shared/` 位置正确、无嵌套副本。
4. **运行时残留清理**：交付副本内不得带 `classroom.db* / exports / logs`。
5. **文档同步**：涉及功能/流程变更时同步 `06_交付说明`、使用手册与（必要时）`00` 文档目录。

## 三、专项审查（按改动类型触发）

| 改动类型 | 必做专项 |
|----------|----------|
| 涉及全屏层/弹窗/遮罩 | **遮罩审计**：每个 `position:fixed` 层初始 `hidden` 且 CSS 有 `[hidden]` 覆盖或全局 `[hidden]{display:none!important}` 兜底（防"启动即盖屏拦截点击"回归） |
| 涉及并发/广播/策略 | **并发压测**：`node test/stress.sim.js 25`（≥25 台登记/任务/归还全达标、P95 延迟、服务端零错误） |
| 涉及数据模型/迁移 | 旧库列迁移（`_migrate`）与 JSON 后端双后端验证；修复后跑 `run-tests.sh --full` |
| 涉及学生端交互 | 实机 GUI 目检：登记 → 任务 → 归还 → 关机演练（含遮罩自动消失） |

## 四、推送规则

1. 只允许在**全量审查全绿**后推送；使用脚本自动把关：
   ```bash
   bash check-and-push.sh "提交说明"      # 审查通过才 commit+push；失败即中断
   ```
2. 提交规范：`feat/fix/docs/chore: 说明`（中文说明，正文写清影响面与验证结果）。
3. 重要节点打 tag（如 `v4.2-deliverable`），便于回退到交付版本。
4. 沙箱环境无法读取 GCM 凭证时，由用户在桌面终端执行 `git push`（脚本会提示命令）。

每次审查结论写入：
- `课堂管理系统_真机测试前自检结果清单.md`（问题与修复）
- 工作区记忆 `.workbuddy/memory/YYYY-MM-DD.md`（含验证数据与坑）
