## 1. 引言

### 1.1 编写目的
本文档定义课堂管理系统的功能需求、非功能需求与用户角色，作为后续架构设计、接口设计、数据库设计与界面原型的输入，也是开发、测试与验收的依据。

### 1.2 项目背景
初二信息技术硬件实践课中，教师需在课前完成点名与器材领取核对、课中掌握各组进度、课后清点归还器材。传统人工流程占用大量教学时间。本系统以物联网消息服务（SIoT2/EasyIoT）为通信底座，学生机作为终端上报状态，教师端大屏实时聚合展示，目标是把"进度同步"与"器材管理"的耗时降到最低，让教师专注教学。

### 1.3 术语定义
| 术语 | 说明 |
| --- | --- |
| SIoT2 | 面向中小学的轻量级 MQTT 物联网服务器，支持主题（Topic）发布/订阅与消息持久化。 |
| EasyIoT | 同类物联网服务平台，兼容 MQTT 协议，可作为 SIoT2 的替代部署。 |
| MQTT | 轻量级发布/订阅消息传输协议，基于 TCP。 |
| QoS | 服务质量等级：0（至多一次）、1（至少一次）、2（恰好一次）。 |
| 大屏看板 | 教师机/投影端运行的 Web 聚合展示界面。 |
| 学生机客户端 | 安装在每台机房 PC 上的轻量应用（Web 或桌面封装）。 |
| 小组/座位 | 机房按座位编排，可 1~4 人一组；系统以"小组"为状态管理单元。 |
| 器材 | 实践课所用硬件套件（开发板、传感器、连线等），需借用与归还登记。 |

### 1.4 参考资料
- MQTT 3.1.1 / 5.0 协议规范
- SIoT2 部署与主题命名说明
- 学校机房环境说明（约 40–50 台 PC，千兆内网）

## 2. 总体描述

### 2.1 产品目标
- 替代人工点名、器材统计、进度问询，降低课堂事务性耗时。
- 提供"课前登记 → 课中互动 → 课后收尾 → 数据导出"的全流程数字化闭环。
- 教师可在大屏一眼掌握全班到课、器材、进度与求助情况。

### 2.2 用户特征
| 用户 | 特征 | 对系统的期望 |
| --- | --- | --- |
| 初二学生 | 12–14 岁，操作能力有限，注意力易分散 | 界面极简、按钮大、三步内完成操作 |
| 信息教师 | 熟悉基础 IT 操作，需管理课堂 | 大屏一目了然、一键导出、少配置 |
| 部署/管理员 | 学校机房管理员 | 一次部署、可批量下发、易维护 |

### 2.3 运行环境
- 学生机：Windows 7/10/11 机房 PC，约 40–50 台并发。
- 服务端：内网一台服务器或教师机运行 SIoT2（MQTT Broker）。
- 教师端：教师机或大屏浏览器，分辨率建议 ≥ 1920×1080。

### 2.4 设计与实现约束
- 单次用户操作不超过 3 步（点开→填写/点按→确认）。
- 支持标准机房 40–50 台学生机并发稳定运行。
- 数据传输稳定可靠，断线后自动重连并补传关键状态。
- 通信基于 SIoT2/EasyIoT（MQTT），不依赖公网。
- 仅输出开发文档，不含教程与代码实现。

### 2.5 假设与依赖
- 机房处于同一局域网，SIoT2 服务可达（默认端口 1883）。
- 学生机具备唯一标识（机房编号/座位号/网卡 MAC 可映射）。
- 教师机可访问 SIoT2 与本地数据库（SQLite）。

## 4. 功能需求

> 编号规则：FR-<序号>，优先级 P0（必备）/P1（重要）/P2（增强）。

### 4.1 课前登记
**FR-01 上课启动（P0）**
- 参与者：教师
- 前置：系统已连接 SIoT2，处于"未上课"态。
- 主流程：教师在大屏点击「开始上课」→ 系统创建课堂会话（session）→ 向全体学生机广播"上课"指令 → 学生机进入登记界面。
- 后置：大屏显示到课统计为"等待登记"态。

**FR-02 学生信息登记（P0）**
- 参与者：学生
- 主流程：学生机展示登记表单（姓名、学号/座位号、所属小组）→ 学生填写 → 点击「确认登记」。
- 约束：必填项校验；提交后本机锁定为"已登记"，仅可查看不可改（除非教师重置）。
- 替代流程：信息预填（管理员导入座位表后，学生仅需核对确认，一步完成）。

**FR-03 器材领取登记（P0）**
- 参与者：学生
- 主流程：登记表单含"本组领取器材"清单（勾选/数量）→ 学生核对实物后确认 → 上报。
- 后置：大屏按小组/器材聚合"已领/未领"数量，替代人工器材统计。

**FR-04 实时汇总大屏（P0）**
- 参与者：教师（查看）
- 主流程：每收到一条学生登记/领取消息，大屏实时刷新到课人数、未登记名单、器材领取率。
- 验收：50 台并发登记，数据在 1 秒内反映到大屏。

### 4.2 课中互动
**FR-05 发布任务（P0）**
- 参与者：教师
- 主流程：教师点击「发布任务」→ 填写任务名称/说明（可选项）→ 广播至学生机 → 学生机高亮当前任务并提示可反馈状态。

**FR-06 任务状态反馈（P0）**
- 参与者：学生
- 主流程：学生完成任务点「已完成」；遇到困难点「求助」；开始做点「进行中」。
- 约束：单次点击即上报（≤1 步），并带时间戳与小组号。

**FR-07 小组状态实时显示（P0）**
- 参与者：教师
- 主流程：大屏以小组矩阵色块展示状态（未开始/进行中/已完成/求助）。
- 关键：出现"求助"时高亮闪烁并置顶提示，便于教师快速定位需指导小组。

### 4.3 课后收尾
**FR-08 下课启动（P0）**
- 参与者：教师
- 主流程：教师点击「下课」→ 创建收尾阶段 → 广播"归还器材"指令 → 学生机切到归还确认界面。

**FR-09 器材归还确认（P0）**
- 参与者：学生
- 主流程：学生对照实物清点 → 勾选"已全部归还" → 点击「确认归还」。
- 后置：大屏显示各组归还完成情况。

**FR-10 全部确认后自动关机（P0）**
- 参与者：系统/学生机
- 主流程：教师端监测到所有小组均「确认归还」→ 向全体学生机下发「关机」指令 → 学生机执行操作系统关机。
- 异常：若有小组未确认，教师可「提醒未确认组」或「强制关机」。

### 4.4 数据导出
**FR-11 一键导出报表（P0）**
- 参与者：教师
- 主流程：教师点击「导出」→ 选择范围（本次/历史）→ 选择格式（Excel .xlsx / CSV）→ 生成文件并下载。
- 导出内容：① 学生登记表 ② 任务完成记录 ③ 器材使用情况 ④ 课堂事件日志。
- 约束：导出不阻塞大屏实时刷新。

### 4.5 通信可靠性
**FR-12 断线自动重连（P0）**
- 参与者：学生机/教师端
- 主流程：客户端检测到 MQTT 断开 → 指数退避重连（1s→2s→4s…，上限 30s）→ 重连成功后补发未确认的关键状态（登记/归还）。
- 验收：模拟断网 30 秒后恢复，关键状态不丢失。

**FR-13 连接状态指示（P1）**
- 学生机与教师端均常驻显示「已连接/重连中/已离线」标识，离线时禁用提交并提示。

## 5. 非功能需求

### 5.1 性能
- NFR-P1：支持 50 台学生机同时在线，MQTT 连接数 ≥ 50。
- NFR-P2：学生操作上报到大屏可见延迟 ≤ 1 秒（局域网内）。
- NFR-P3：大屏聚合刷新频率 ≥ 1 Hz，且为增量渲染不卡顿。
- NFR-P4：课堂数据导出（单次 ≤ 50 人 × 多表）耗时 ≤ 3 秒。

### 5.2 可靠性
- NFR-R1：关键消息（登记/归还/求助）使用 QoS=1，至少一次送达。
- NFR-R2：断线重连成功率 100%（网络恢复后），关键状态幂等补传。
- NFR-R3：学生机异常退出/断电后，已上报数据不丢（服务端持久化）。

### 5.3 易用性
- NFR-U1：任意核心操作路径 ≤ 3 步。
- NFR-U2：主操作按钮尺寸 ≥ 80×80 px，文字 ≥ 18 pt。
- NFR-U3：状态用颜色+图标双重表达，降低阅读门槛。
- NFR-U4：提供大屏"一键"主控制（上课/下课/导出/关机）。

### 5.4 兼容性
- NFR-C1：学生机客户端支持 Windows 7/10/11（32/64 位）。
- NFR-C2：教师端为浏览器应用，兼容 Chrome/Edge 最新两版。
- NFR-C3：SIoT2 与 EasyIoT 双后端可切换（配置项）。

### 5.5 安全性
- NFR-S1：仅运行于内网，不向公网传输任何数据。
- NFR-S2：不采集与课程无关的隐私（无摄像头/麦克风）。
- NFR-S3：SIoT2 启用账户密码认证，禁用匿名写入。

### 5.6 可维护/可部署
- NFR-M1：学生机支持批量静默部署（配置文件含 SIoT2 地址/主题前缀）。
- NFR-M2：机房座位表、器材台账为可编辑配置文件/表，便于每学期更新。
