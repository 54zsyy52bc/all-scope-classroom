# 第一部分 · 总则

## 1. 目标与适用范围

在"改动"进入基线前回答三类问题：
1. **对不对、稳不稳**（代码审查：正确/安全/性能/测试）；
2. **顺不顺、懂不懂、怕不怕**（UX 审查：旅程/术语/反馈/防误）；
3. **配不配对**（交互成对：学生端提示 ↔ 教师端操作，双向闭环）。

适用范围：`classroom-mgmt/{teacher,student,preset-studio,shared}`、`scripts/`、交付包配置及任何新增源码。
审查对象 = **待合入的 diff + 它影响的用户旅程**。

## 2. 审查原则（九条，合并原 CR + UX）

| # | 原则 | 含义 |
|---|------|------|
| P1 | 对事不对人 | 讨论代码与旅程，不评判作者。 |
| P2 | 每条意见可执行 | 位置 + 问题 + 为什么 + 改法；只说"不好"等于没说。 |
| P3 | 分级不刷屏 | 见 §4 两套分级；宁可少而准，不可多而噪。 |
| P4 | 先赞后批 | 好设计点名表扬，好行为才会被复制。 |
| P5 | 一次审完 | 一次给全意见，禁止挤牙膏式分批评论。 |
| P6 | 旅程优先（UX） | 不审查"好不好看"，审查"任务能否顺畅做完"；以初二学生/忙碌教师为基准。 |
| P7 | 术语即契约（UX） | 用户可见词全系统唯一；漂移 = 缺陷。 |
| P8 | 状态可见 > 功能存在 | 用户得知道在哪、为何被禁用、下一步是什么。 |
| P9 | 提示必有解（配对） | 任何"请老师/举手/联系老师"文案，教师端必须有真实可达操作。 |

## 3. 角色与责任

| 角色 | 责任 | 禁止 |
|------|------|------|
| 作者 | 自检、开 PR（标注改动分级）、回应评论、修 🔴/🟡 | 自我 Approve、静默合入含 🔴 PR |
| 主审 | 按改动分级执行对应清单（§6/§7） | LGTM 党、刷屏 |
| UX 走查员 | 非作者；C2 及以上若涉及旅程，执行剧本走查 | 作者自审 UX |
| 安全审（按需） | C3 必配；审 安全专项清单 | —— |
| 把关人（Owner） | 裁决分级与争议、确认 🔴 关闭、放行 | 未核验就 Approve |

# 第二部分 · 两套分级（先分级，再审）

> ⚠ **区分两个"级"**：**改动风险分级**（对 diff 本身，决定审什么、谁来审）与**问题严重度分级**（对审查意见，决定能否合入）。前者在开 PR 前确定，后者在审查中产生。

## 4. 分级体系

### 4.1 A. 改动风险分级（Change Class：C0~C3）

| 级 | 名称 | 一句话 | 典型例子 |
|----|------|--------|----------|
| **C0** | 琐碎 | 行为不变的维护 | 注释、格式化、纯文档、CSS 变量改名、只读日志调整 |
| **C1** | 常规 | 单点低风险行为改动 | 单函数 bugfix（≤150 行）、服务端某校验加强、局部样式 |
| **C2** | 重要 | 触碰状态机/接口/文案/双端 | 新增路由或 SSE 事件、阶段/计时/策略逻辑、**学生端可见文案**、交互成对新增、DB 加安全列、导出/导入格式调整 |
| **C3** | 高影响 | 协议/安全/schema/全端 | shared 契约（topics/preset-package/信封）、HMAC/关机/鉴权/CORS、schema 迁移含存量数据、三端联动、交付包/发布、>600 行 |

**判定方法**：先查 §5.1 评分卡；命中任一"一票升档"项直接取高级；再按得分累计兜底。

### 4.2 B. 问题严重度分级（Issue Severity：🔴/🟡/💭）

| 级别 | 定义（代码语境） | 定义（UX/配对语境） | 处置 |
|------|------------------|----------------------|------|
| 🔴 阻断 | 安全漏洞/数据损坏/不可恢复故障/破坏契约 | 用户无法完成任务的旅程中断或误导性不可逆操作 | **必须修复后合入** |
| 🟡 应改 | 边界校验缺失/性能隐患/注释与实现矛盾/缺关键测试 | 强困惑强摩擦：术语冲突、误导反馈、可见却被拒 | 本 PR 修或建 Issue，把关人同意放行 |
| 💭 建议 | 风格/命名/文档打磨 | 轻微摩擦、文案与无障碍增强 | 作者自定，进 backlog |

> 记忆口诀：改动分级问"**这改动多大动静**"；问题分级问"**这问题多严重**"。

# 第三部分 · 分级判定与阈值

## 5. 如何判定一次改动的等级

### 5.1 评分卡（开 PR 时作者填，审查者复核）

| 维度 | 计分 | C0 | C1 | C2 | C3 |
|------|------|----|----|----|----|
| diff 行数 | ≤20→0；≤150→1；≤600→2；>600→**C3** | ● | ● | ● | ● |
| 文件数 | ≤1→0；≤3→1；>3→2 | ● | ● | ● | ● |
| 涉及端数 | 1 端→0；2 端→2；3 端→**C3** | ● | ● | ● | ● |
| 共享契约 topics.js / 信封 / preset-package | 触碰→**C3** | | | | ● |
| 关机/HMAC/鉴权/CORS/绑定地址 | 触碰→**C3** | | | | ● |
| DB schema（加列/迁移/存量数据） | 触碰→2；含存量改造→**C3** | | | ● | ● |
| 阶段机/计时/策略逻辑 | 触碰→2 | | | ● | |
| 新增路由 / SSE 事件 / MQTT 新 action | 触碰→2 | | | ● | |
| **学生端可见文案/状态页/交互** | 触碰→2（强制走 配对 + UX） | | | ● | |
| 教师端新操作入口 | 触碰→1 | | ● | | |
| 术语词表/UI 布局流程 | 触碰→1 | | ● | | |
| 数据导出/导入格式 | 触碰→1 | | ● | | |

**判定规则**：得分 0 → C0；1 → C1；≥2 → C2；出现"C3 一票项"或总分 ≥4 → C3。得分与直觉不符时**取高不取低**（升档永远安全，降档需把关人同意）。

### 5.2 一票升档（C3）清单（红线项）
改到以下任何一处，无论行数多少一律 C3：
1. `shared/topics.js`、信封结构、`shared/preset-package.js` 或任何双端/三端契约；
2. 关机链路（command.service 关机/撤销、HMAC 令牌、学生端 executeShutdown）；
3. 鉴权（ENABLE_AUTH/CORS/监听地址/TEACHER_TOKEN）；
4. DB schema 迁移且需改造存量数据；
5. 一次改动同时触碰 teacher+student+preset-studio 三端。

### 5.3 阈值速查（超出即升档）

| 阈值项 | C0 | C1 | C2 | C3 |
|--------|----|----|----|----|
| 最大 diff 行 | 20 | 150 | 600 | 不限（但 >600 建议拆） |
| 最多文件 | 1 | 3 | 8 | 不限 |
| 最多涉及端 | 0 端改动源码 | 1 | 2 | 3 |
| 学生端文案 | 禁止 | 禁止 | 允许（必走配对） | 允许 |
| 路由/SSE/MQTT 新 action | 禁止 | 禁止 | 允许 | 允许 |
| 协议/安全/schema 存量 | 禁止 | 禁止 | 禁止 | 允许 |

## 7. 审查内容（必查清单全集）

### 7.1 通用清单（C1+ 全查）
- [ ] 正确性：边界值（0/负/超长/空/null）、状态机非法迁移、时间处理
- [ ] 安全：校验在服务端；入 HTML/CSV/SQL/命令的数据已净化
- [ ] 可维护：命名表意、单一职责、注释解释"为什么"
- [ ] 性能：循环内查库 N+1、全表扫可否过滤、大对象全量传输
- [ ] 测试：核心行为 + 本次变更的快乐/异常路径
- [ ] 错误处理：关键路径有兜底；无裸吞异常（`catch(_e){}` 须带注释）
- [ ] 契约：共享模块是否双端同步；openapi/文档是否同步

### 7.2 分层清单（按触碰层查）
- **服务端**：路由薄/服务层承载业务；写库走仓储与 `transaction`；事件 `msg_id` 幂等与业务写同事务；新增表/列同步 TABLES/PK/DDL/_migrate；定时器考虑重启恢复
- **MQTT**：越界座位忽略、未知 type 忽略、单条坏消息不打断流；前置校验先于 insertEvent；SSE 广播在事务后
- **前端/渲染**：用户数据入 innerHTML 过 esc()；表单乐观置位+失败回滚；触控 ≥80px；无硬编码色
- **Electron 主进程**：渲染层不可信、白名单 IPC、secret/fs/child_process 不进 preload；关机终裁在主进程
- **导出**：CSV 公式注入净化（`= + - @ \t \r` 前缀 `'`）；文件名/路径穿越白名单

### 7.3 安全专项清单（C2 触碰安全项 / C3 必查）
- [ ] 鉴权默认拒绝（CR-02 R-1 教训）
- [ ] 监听地址最小暴露、CORS 白名单化
- [ ] 密钥比较 `timingSafeEqual`
- [ ] 学生隐私（姓名/学号）无泄露面（日志/API/CSV）
- [ ] 关机"校验+执行"不可被渲染层绕过

### 7.4 交互成对必查（触碰学生端文案/教师端新操作时）
- [ ] 学生端每条提示 → 教师端**对应、可达（按阶段可见）、完整**入口？（P9）
- [ ] 反向：教师端操作 → 学生端**可感知反馈**？
- [ ] 控件可见阶段 = 服务端放行阶段（禁"能点必被拒"）
- [ ] 新交互写入交互矩阵（§7.7），状态 = 闭环/断链挂单
- [ ] 机器防线：`scripts/verify-pairing.js` 通过

### 7.5 UX 启发式（触碰文案/流程时）
- [ ] 状态可见：阶段/连接/等待原因/禁用原因明确
- [ ] 防误容错：危险操作有后果预览；失败 = 中文原因 + 下一步（**禁止裸 errorCode/英文原语**）
- [ ] 文案：placeholder 具体可模仿；无技术 token（SIoT/task/eqId）直出用户
- [ ] 一致性：状态词/动作名/阶段名全系统唯一（查词表）；颜色语义一致
- [ ] 可达性：模态自动聚焦、键盘可操作、aria 语义、投屏可读
- [ ] 低龄友好：初二学生 3 秒能懂、教师 3 米能看清关键态

## 8. 端到端流程（提交前 → 合入 → 复盘）

### 8.1 提交前自检（作者，每次必做）
1. 判级：填 §5.1 评分卡，得出 C0~C3，写进 PR 标签（如 `risk:C2`）；
2. 门禁 + 语法 + 相关测试；
3. 按分级命中 §6 矩阵的行，逐条自查；
4. 自读 diff：无调试残留、注释与实现一致。

### 8.2 PR 流程（按级）
- **C0**：作者自跑门禁后可合入（仍建议在提交说明标 C0），无需 Approve；
- **C1**：1 名非作者主审 Approve（响应 ≤4h）；把关人不必；
- **C2**：主审（非作者）通读 + 把关人 Approve；必过 §7.1/7.2 + 触碰项（7.3/7.4/7.5/7.6）；跑 `run-tests.sh` + `verify-pairing.js`；UX 剧本 ≥1（若涉旅程）；
- **C3**：≥2 名审查（其一安全视角）+ 把关人；跑 `--full` + `verify-pairing`；契约双端 diff；发布走查；交互矩阵/词表同步；回归记录落文件。
- 任何一级：🔴 未清不得合入；🟡 处理或挂单。

### 8.3 合入完成定义（DoD，按级裁剪）
C0：门禁过。｜ C1：+主审 Approve、无 🔴。
C2：+把关人 Approve、相关测试与回归过、🟡 处理或挂单、交互矩阵同步。
C3：+双审/安全审、全量测试、契约核验、回归记录文件、发布走查过。

### 8.4 特殊流程
- **hotfix**：可先合入后 24h 补审（标注 `[hotfix]`），补审按原级执行；
- **发布前走查**：版本基线 = 全量源码走查 + `--full` + 交互矩阵全绿 + 交付包一致性；
- **专项审计**：安全敏感（C3 语义）或事故复盘时触发。

## 9. 自动化门禁与机器防线（常驻）

```bash
# 质量门禁（现有）：单文件 ≤300 行（db ≤320）/ 无 emoji / 无硬编码色 / 按钮 ≥80px
# UX/交互机器防线（每次发布 + C2+ 改动）：
grep -rnE "window\.(confirm|prompt|alert)" teacher student preset-studio --include="*.js"   # 期望 0（原生弹窗）
grep -rn "errorCode.*message\|当前阶段 \${" teacher/src teacher/public --include="*.js"      # 错误原语直出扫描
node classroom-mgmt/scripts/verify-pairing.js                                                # 交互闭环回归 15/15
grep -rn "请老师\|联系老师\|举手告知\|等待老师" student/renderer --include="*.js"              # 待教师文案 → 对照矩阵 P#
```
新增：`risk:C*` 标签强制进 PR 标题；机器人/脚本自动拒绝"无分级标签"的 C2+ 猜测项可后续接入。

## 10. 度量与复盘
审查覆盖率 100%；缺陷逃逸率 <10%（发布后 2 周 🔴/🟡 / 该版本总数）；C3 全量走查率 100%；
分级准确率（把关人复核 vs 作者自评，不一致 → 复盘判级理由）。每周例会 5 分钟：本周 🔴 + 最有价值发现 + 分级误判案例。

## 11. 文档地图与历史
