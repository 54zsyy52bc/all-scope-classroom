# UX 审查报告 · ALL SCOPE 课堂管理系统 v4.2

> 审查日期：2026-09-06 ｜ 审查者：代码审查专家（UX 视角）
> 方法：三端界面源码走查（teacher/public、student/renderer、preset-studio/renderer）+ UIUX_v1 设计规范对照 + 术语跨端 grep + 主流程剧本推演
> 范围：文案术语、阶段状态可见性、防误容错、反馈机制、表单校验、可达性基础、设计规范符合度

---

## 一、总体结论

**用户体验设计底子很好：主流程叙事清晰、反馈机制齐全、面向低龄用户做了大量贴心细节。问题集中在"一致性"层——术语漂移、反馈通道混用、文案漏出技术原语。无任务完全中断级（🔴）缺陷，但有多处强困惑（🟡），发布前值得收敛。**

值得表扬的 UX 细节（建议作为团队范式保留）：
1. **学生端全屏阶段叙事**：待课/登记/任务/归还/结束各有完整页面 + 图标 + 下一步引导，且页面随教师动作**自动切换**（`views.js` 纯函数渲染 + 委托事件，职责清晰）。
2. **乐观更新 + 防重复 + 离线告知**：提交即置位、1.5s 后 hello 回校服务端真值；离线提交明确 toast"操作暂未送出"（`actions.js:56-76`、`app.js:141`）。
3. **低龄用户友好细节**：器材步进器禁用态与 aria-label（`views.js:44-48`）、归还"全部已放回器材柜"主按钮、归还空态给"请联系老师补登"的出路、归还完成页"如果还要用电脑请举手告知老师"（`views.js:183-184`）、锁屏区分"教师讲解中"原因 + 计时截止 beep。
4. **教师大屏驾驶舱设计**：按钮按阶段显隐（`data-phase-vis`）、模态首字段自动聚焦 + 回车提交、事件时间线日志、预演式导入确认、导出自动触发多文件下载。
5. **占位文案具体可模仿**（"例如：陈书瑶 / 焊接练习 / 开发板 USB 口松动"）——对零培训用户极重要。

## 二、🟡 应改问题

### U-1 核心概念术语漂移：「任务」与「活动」跨端、甚至同屏混用

**证据（同一实体 user-facing 三套叫法）**：
- 教师大屏：按钮「**发布任务**」（`teacher/public/index.html:41`）→ 点击弹出的模态标题却是「**发布活动**」（同文件 :98）、下拉「活动预设」；统计区「任务完成」（:35）；座位徽标状态 doing/done/help（`app.js:21`）。
- 学生端：等待页「等待老师发布**任务**」（`student/renderer/views.js:151`），但计时状态文案「**活动**进行中 / **活动**已截止」（`views.js:139`）。
- Preset Studio：页签「**活动**预设」内含「**任务**模板」（`preset-studio/renderer/index.html:71`）。
- 后端/文档本来就混用（`t_task` 表、`/activities` 路由、README"发布任务/活动"）——代码内部无所谓，但**用户可见文案必须收敛**。

**为什么**：初二学生与教师在课堂上口头协同（"老师发布了任务/活动？"），三端叫法不一致会造成即时误解；同屏"按钮叫任务、弹窗叫活动"最伤——用户会怀疑自己点错了。这是 UX 术语契约问题，功能正确但认知混乱。

**建议**：制定并执行术语词表（见 §三），对外文案全链统一。推荐统一为**「活动」**（与弹窗/Preset Studio 页签/计时文案一致面更广），把教师端按钮"发布任务"改"发布活动"、学生端"等待老师发布任务"改"等待老师发布活动"；内部表名/API 不改。同步扫掉 05/07 文档中用户视角的旧词。

### U-2 危险/输入交互全部使用浏览器原生 confirm/prompt，与设计体系割裂且无容错

**证据**：`teacher/public/app.js:218,224,230,236`（下课/结束/关机/重置）、`activity.js:199`（结束计时）、**`:201` 调整时长用 `window.prompt`**、`manage.js:57,63`、`preset-studio/renderer/presets.js:78,217`、`app.js:113` —— 共 **10+ 处**。

**为什么**：
1. 与 UIUX_v1 规范的自定义 modal 体系（页面内 `overlay-start/overlay-task` 深色样式）**视觉割裂**——原生对话框是系统浅色，在大屏深色主题/投影下突兀；
2. `prompt` 调整时长**非法输入静默失败**：取消、字母、>120 时 `activity.js:203-204` 直接不动作，无任何提示——教师以为按钮失灵；
3. 原生对话框无法定制文案层级与误触防护，无法投影缩放。

**建议**：抽一个统一 `confirmModal(title, desc, danger)` 与 `promptModal` 组件（复用现有 overlay/modal 样式与焦点管理）；时长调整建议改为"行内编辑 + 数字步进（±1/±5 分钟）+ 上限提示"，替代 prompt。规则：**全项目禁用原生 confirm/prompt，CI 可 grep 拦截（UX-01 §9）**。

### U-3 错误提示把内部 errorCode 与英文阶段原语直出给教师

**证据**：`teacher/public/app.js:37-39`：`api()` 失败时 toast `(j.errorCode||'') + ' ' + message`——例如大屏会显示 `E-OFF-01 仅在课后归还阶段可下发关机指令，当前阶段 task`。错误文案源头带原始 token：`command.service.js:23`（`${session.phase}`）、`session.service.js:207`（`不能从 ${from} 流转到 ${toPhase}`）。

**为什么**：教师看到的应是"现在不能关机，需要先下课进入归还阶段"，而不是调试信息（错误码 + 英文 task/return）。错误码对用户零价值，还显得系统"没做完"。

**建议**：toast 只显示 message，且服务端业务错误文案内的阶段用中文映射（`PHASE_LABEL` 字典后移或前端统一兜底翻译）；errorCode 仅入日志/事件流。设一条红线：**用户可见错误 = 中文原因 + 可执行下一步，禁止裸 code/token**。

### U-4 大屏「强制关机」按钮可见性与服务端闸门不一致（点了必被拒）

**证据**：`teacher/public/index.html:44`：`btn-shutdown` `data-phase-vis="task return"`——**课中阶段可见**；但服务端 `command.service.js:22-24` 硬性要求 `phase ∈ {return, closed}`，task 阶段调用必返回 E-OFF-01（叠加 U-3 的裸错误文案，体验双重受损）。

**为什么**：两种可能意图——① 课中纪律问题需要能强制关机（那应放开服务端闸门并加确认文案）；② 仅归还阶段可关（那按钮不该在 task 出现）。当前实现两头都不像，用户"看到能点、点了被拒"，是典型的**状态可见性与业务规则脱节**（与代码审查 CR-02 R-1 同根：前后端规则未同步）。

**建议**：先定业务决策，再二选一：按钮只在 `return` 阶段显示；或服务端允许 task 阶段强制关机（带更强的二次确认文案）。无论哪种，同步更新按钮 label 与确认弹窗文案。

### U-5 学生端 step-badge 分步数字自相矛盾且与页面形态不符

**证据**：`student/renderer/views.js:109` 登记页「第 1 步 / 共 3 步」、`:190` 归还页「第 1 步 / 共 2 步」、`:171` 任务页「第 1 步 / 共 1 步」。但三页都是**单屏表单**，页面内没有任何"第 2 步/第 3 步"的入口或导航。

**为什么**：初二学生会问"另外两步在哪？"。若"3 步"指课堂三大环节（登记/任务/归还），则当前显示逻辑（checkin=3、return=2、task=1）也不自洽——同一叙事下三段应是同一总数。

**建议**：删除该徽章，或改为**全课统一的阶段徽标**（如"环节 1/3 · 登记""环节 2/3 · 任务""环节 3/3 · 归还"，三页总数一致且随阶段推进），让学生时刻知道"整节课我进行到哪一步"——后者对课堂工具更有价值。

## 五、健康项（验证通过，无需修改）

- 学生端表单必填校验有行内红色 hint（姓名/座位号），不是提交后弹错（`actions.js:69-73`）；
- 座位号输入 `inputmode="numeric"` + 自动补零 + 服务端二次净化（`views.js:117`）；
- 危险操作（关机/下课/结束/删除）均带后果说明的确认（虽然用原生 confirm，内容本身合格，U-2 只改载体不改文案）；
- 锁屏/解锁/计时截止/器材更新均有 toast 与音效提示，学生端离线提交有明确警告；
- 大屏按钮按阶段显隐（除 U-4 一处）、模态键盘可达、导出多文件自动下载；
- aria 语义基本齐备（`role=dialog/aria-modal/aria-pressed/aria-label`），无 emoji、双主题（学生浅色/教师深色）符合规范。

## 七、结论

UX 基础扎实、无明显旅程死路；本报告聚焦的"一致性缺陷"（术语、反馈载体、可见性与规则脱节）修复成本低、收益立竿见影。建议将 UX-01 规范与词表评审定稿后纳入团队常规，并在每次发布前跑 §9 的机器化扫描（术语漂移 grep / 原生弹窗 grep / 错误码直出 grep），把本次人工发现固化为自动防线。
