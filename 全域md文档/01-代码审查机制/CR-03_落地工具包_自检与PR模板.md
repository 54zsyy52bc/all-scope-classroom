# CR-03 落地工具包 · 提交前自检 / PR 模板 / 审查批注速查

> 配套《CR-01 代码审查标准与流程》。把本文件拆成 PR 模板（§B）与提交前自检（§A）随用随取。

---

## A. 提交前自检清单（作者，合入前 5 分钟）

**测试与门禁**
- [ ] `cd classroom-mgmt && bash run-tests.sh` 通过（涉及 broker/协议改动跑 `--full`）
- [ ] 单文件 ≤300 行（db 仓储/存储 ≤320）；无 emoji；无硬编码色；按钮 ≥80px
- [ ] 无调试残留：`console.log/debugger/TODO/FIXME` 已清理或注明

**安全自查（本仓库红线）**
- [ ] 新增用户输入 → 服务端有兜底校验（座位 1-99、信封 type、状态枚举…）
- [ ] 数据进 HTML/CSV/SQL 前已净化（`esc()` / 参数化 / CSV 公式注入前缀）
- [ ] 未引入新的占位凭据/密钥硬编码；shared 契约双端同步改
- [ ] 定时器/后台任务：进程重启后能恢复（参考 S-1）或有明确降级

**质量**
- [ ] 新增/修改行为有测试（快乐路径 + ≥1 异常路径）
- [ ] diff 自读一遍，能讲清"为什么这么改"

## B. PR 描述模板

```markdown
## 变更摘要
<!-- 一句话：修了什么 / 加了什么 -->

## 关联
- 需求/缺陷：#issue ｜ 文档：全域md文档/02-开发与设计文档/0X_*.md
- [hotfix] 事故链接（紧急修复必填）

## 变更内容
- [ ] 功能/修复描述（含行为变化）
- [ ] 涉及端：teacher / student / preset-studio / shared / 交付包
- [ ] 契约影响：openapi.yaml / topics.js 是否同步（如涉及请勾选）

## 测试
- [ ] 自动化：`run-tests.sh`（或 `--full`）结果
- [ ] 手工验证步骤（简要）
- [ ] 风险点与回滚方案

## 自查
- [ ] 已过《CR-03 §A 提交前自检清单》
```

## C. 审查批注速查（评论话术模板）

```
🔴 **<类别：如 安全/数据完整性> <标题>**
位置：文件:行号
问题：…
为什么：…
建议：…（含最小改法示例）
```

| 场景 | 参考话术 |
|------|----------|
| 指出问题 | "🔴 这里 `msg_id` 落库在业务写入之前且不在同一事务，MQTT 重投时…建议…" |
| 不懂就问 | "这段 `deriveGroup` 的推导与种子分组不一致，是故意兼容旧数据吗？" |
| 表扬 | "👍 越界座位在校验阶段就忽略、不占 msg_id，这个细节避免了统计污染" |
| 轻微建议 | "💭 可考虑抽成 `sanitizeCell()` 并配单测，职责更清晰" |

## D. 红线速查（违规即 🔴）

1. 字符串拼 SQL / 非白名单列名
2. 占位默认凭据上线（HMAC_SECRET / broker 口令）
3. 前端校验当安全边界（服务端必须复检）
4. 用户数据未净化进 innerHTML / CSV / 日志
5. 共享契约单端修改
6. 状态机裸 update phase（绕过 ALLOWED）
7. 裸 `catch(_e){}` 无注释
8. 服务监听 0.0.0.0 且无鉴权（见 CR-02 R-1）
